## Known Auth / Permission Gaps (verified facts — cite before touching any of these controllers)

- **AdminController has no role guard at all.** `apps/backend/src/admin/admin.controller.ts` only relies on the global `JwtAuthGuard` — GET `/admin`, GET `/admin/:admin_id`, PATCH `/admin/:id`, PATCH `/admin/username/:username` are reachable by any authenticated user regardless of role.
- **`POST /super-admin/register` has no role check.** `apps/backend/src/super-admin/super-admin.controller.ts` — any authenticated user (any role) can create a super-admin account. `POST /super-admin/create-admin` and `GET /super-admin/:super_admin_id` perform manual in-controller role checks instead of using `RolesGuard`.
- **`DatabaseSyncController`'s trigger endpoints have no role guard.** `POST /database-sync/sync` and `POST /database-sync/biostar/sync` in `apps/backend/src/database-sync/database-sync.controller.ts` are JWT-only (no `@Roles`), while sibling endpoints on the same controller (`/schedule`, `/schedules`, `/biostar/schedule`, `/biostar/schedules`, `/test-connection`, `/running-syncs`, `/delete-users`) correctly require `@Roles(ADMIN, SUPER_ADMIN)`.
- **Role-string casing bug.** `apps/backend/src/login/login.service.ts:108` signs admin-login JWTs with the literal `role: 'ADMIN'` (uppercase), but `Role.ADMIN` in `apps/backend/src/auth/enums/role.enum.ts` = `'admin'` (lowercase). Any `@Roles(Role.ADMIN)` check (e.g. `UsersController` bulk-deactivate/reactivate, `EmployeeController` POST/PATCH) never matches tokens issued via the admin-login path — only super-admin-issued tokens pass those checks correctly.
- **`ReportsGateway` websocket has no auth guard at all** (`apps/backend/src/reports/reports.gateway.ts`, Socket.IO path `/socket.io/`, event `stats-update`) — broadcasts gate-access stats to any connected client.
- **`GET /health` is not `@Public()`** — inherits the global `JwtAuthGuard`, so an unauthenticated load-balancer probe would receive a 401.
- **Backend has no global `ValidationPipe`** (`apps/backend/src/main.ts`) — most DTOs across all controllers below are unvalidated at the framework level.
